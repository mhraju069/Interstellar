# Interstellar Scroll Website: Build Plan

A scroll-driven cinematic website. 4 scenes, each a folder of pre-generated video frames.
Scrolling plays the frames on a single `<canvas>`. Starts on black, ends on black, then space-themed text sections appear.

Priorities: (1) buttery smooth, (2) lightweight, (3) cinematic feel.

---

## 1. Tech Stack (keep it light)

| Purpose | Choice | Why |
|---|---|---|
| Build | **Vite** (vanilla JS/TS, no framework) | Tiny bundle, fast |
| Smooth scroll | **Lenis** | Inertia scrolling, works with ScrollTrigger |
| Scroll logic and animation | **GSAP + ScrollTrigger** | Industry standard, pinning, scrub |
| Frame rendering | **Canvas 2D** | Faster and lighter than swapping `<img>` or `<video>` |
| Text 3D effects | **CSS 3D transforms** driven by GSAP | No Three.js needed, keeps it light |
| Starfield (end section) | Tiny canvas particle layer (~150 dots) | Optional, cheap |

Do NOT add: Three.js, React, jQuery, large UI kits. Total JS target: under 150 KB gzipped.

## 3. Step 0: Optimize Frames (most important for performance)

Raw JPG/PNG frames are too heavy. Convert to WebP before anything else.

- Resolution: **1280x720** (desktop). Optional mobile set: **854x480** in `public/frames-m/`.
- Format: **WebP quality 72-78**. Target **30-70 KB per frame**.
- Naming: `f_0001.webp`, zero-padded, 4 digits.
- Run: `bash scripts/optimize-frames.sh`
- Script also writes `public/frames/manifest.json`, e.g.
  `{"scenes":[{"id":1,"dir":"scene-1","count":180},...]}`

Rule of thumb: total frames across 4 scenes of 400-800 is fine. If you have more, skip every 2nd frame for mobile.

## 4. Architecture

### 4.1 One global canvas
- A single `<canvas>` is `position: fixed; inset: 0` behind everything.
- Scene 1 to 4 are treated as ONE long continuous sequence of frames (global index).
- Canvas internal size = viewport x `min(devicePixelRatio, 1.5)`. Never higher, it wastes GPU.
- Draw with "cover" fitting (like CSS `object-fit: cover`), centered. Keep the spacecraft's area safe on mobile (see 4.6).

### 4.2 Scroll mapping
- A tall scroll container (`#scroll-track`) drives progress `p` from 0 to 1.
- Timeline of `p`:
  - `0.00 - 0.06`: **black to scene 1 first frame** (fade in from black)
  - `0.06 - 0.88`: **frames play**, scenes 1, 2, 3, 4 in order (weighted by frame count)
  - `0.88 - 0.94`: **fade out to black**
  - `0.94 - 1.00`: black hold, then text section takes over
- Track height: about `frames_total * 6px` (tune 5-8px/frame). More px per frame means slower, smoother playback.

### 4.3 Smoothing (critical)
Do not set the frame directly from scroll. Use a lerp:

```js
target = p * (totalFrames - 1);
current += (target - current) * 0.12;   // 0.08 = floaty, 0.2 = snappy
draw(Math.round(current));
```

- Run in one `requestAnimationFrame` loop (or GSAP ticker). Only draw when the rounded frame changed.
- Lenis handles scroll inertia, so lerp factor can stay around 0.12.

### 4.4 Scene transitions
- Scenes are separate videos, so there may be a visible jump at scene edges.
- Add a **crossfade over ~8 frames**: draw frame N of scene A, then frame M of scene B on top with `globalAlpha` ramping 0 to 1.
- Optionally add a very subtle scale (1.00 to 1.03) during the crossfade to hide the cut.

### 4.5 Loading and memory strategy (do NOT skip)
Decoded 1280x720 images use ~3.5 MB RAM each. 600 frames decoded = 2 GB. Will crash phones.

- **Phase 1 (blocking, with loader screen):** load first ~40 frames of scene 1. Show a thin black loader with a progress line. Then start.
- **Phase 2 (background):** fetch remaining frames in order of scene, 4-6 parallel requests, so they sit in the HTTP cache.
- **Sliding decode window:** keep only frames `current-10 ... current+40` as decoded `Image`/`ImageBitmap`. Release the rest (set to `null`). Re-load from cache on demand.
- If the needed frame is not ready, keep drawing the last ready frame (never a blank flash).
- Use `img.decode()` before drawing.

### 4.6 Responsive
- Mobile (width < 768): use `frames-m` set if present, `dpr` cap 1.25, fewer px per frame (4px).
- Handle `resize` (debounced 150 ms): resize canvas, redraw.
- Use `100svh` units to avoid mobile address-bar jumps.

### 4.7 Accessibility and fallback
- `prefers-reduced-motion`: no lerp, no 3D tilt, simple fade-ins only.
- Provide `<noscript>` message and an alt description for the canvas (`role="img"`, `aria-label`).

## 5. Black Screen Intro and Outro

- Intro: page loads on pure black (`#000`). No text. Frame 1 fades in as the user starts scrolling.
- A tiny hint at the bottom (optional): a thin vertical line pulsing, no words. Fades out after the first scroll.
- Outro: black overlay `<div id="fade">` opacity goes 0 to 1 with `p`. When fully black, the text section is revealed.

---

## 6. Text Sections (after the final black)

Start after the track ends. Background stays black with a faint starfield. Use ScrollTrigger.

### 6.1 Layout
1. **Title reveal** (pinned, 100vh)
2. **Horizontal scroll gallery** (pinned, 4 panels slide left as you scroll down)
3. **Closing line + credit** (fade)

### 6.2 Animations (lightweight, 3D feel)
- **Title:** split text into characters/words (use manual span splitting, no paid plugin). Each rises from `y: 60, rotateX: -80deg, opacity: 0` with stagger 0.03, `transform-perspective: 800px`.
- **Horizontal section:** pin the container, `gsap.to(panels, { xPercent: -100 * (n-1), ease: "none", scrollTrigger: { scrub: 1, pin: true, end: "+=3000" } })`.
- **Each panel:** heading and paragraph have a slight parallax (`x` offset) and a 3D tilt: `rotateY` from 25deg to 0 as the panel enters, back to -25deg as it leaves.
- **Numbers or stats:** count-up animation when entering view.
- **Closing:** slow fade, letter-spacing animates from `0.6em` to `0.2em`.
- Animate ONLY `transform` and `opacity`. Add `will-change: transform` only on actively animating elements.

## 7. Visual Style

- Palette: black `#000`, deep slate `#0b0f14`, warm gold `#f3e3b0` (matches the glow), soft white `#e8e6df`.
- Font: **Cormorant Garamond** or **Inter** (pick ONE display + ONE body). Self-host or Google Fonts with `display=swap`.
- Large, light-weight type, wide letter-spacing, lots of negative space.
- Subtle film grain overlay: a tiny 128px noise PNG tiled, `opacity: .05`, `pointer-events: none`.

---

## 8. Performance Budget

- First load: under 1.5 MB before the intro starts (JS + CSS + first 40 frames).
- 60 fps on mid-range laptop, 30+ fps on mid-range phone.
- No layout thrash: read sizes once on resize, never in the scroll loop.
- Passive listeners only. One rAF loop total.
- Lighthouse Performance goal: 85+.

## 9. Task List (for the coding agent, do in order)

1. Scaffold Vite vanilla project. Install `gsap` and `lenis`.
2. Create `scripts/optimize-frames.sh` and run it on `raw-frames/`. Confirm `manifest.json`.
3. Build `frameEngine.js`: canvas, cover-draw, preloading, sliding window.
4. Build `scrollTimeline.js`: Lenis + ScrollTrigger, progress mapping, lerp loop, crossfade, black fades.
5. Test the full frame sequence with a debug overlay (current frame, scene, fps). Fix jumps.
6. Build text sections and animations (`textSections.js`).
7. Add starfield, grain, loader screen.
8. Mobile pass, reduced-motion pass, resize handling.
9. Performance pass: check memory in DevTools, trim frames or quality if needed.
10. Production build and test with `npm run build && npm run preview`.

## 10. Definition of Done

- Opens on pure black with no text.
- Scroll plays all 4 scenes smoothly with no blank flashes.
- Ends in black, then text sections animate in with horizontal 3D motion.
- Scrolling back up reverses everything cleanly.
- Works on desktop and mobile, no memory crash, no jank.
